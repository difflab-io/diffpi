# Plan

This skill owns the workflow. `/plan` only forwards its raw arguments to `/skill:plan`. Do not emit another command to paste or rely on a command handler to select an agent, parse flags, or inject a workflow. For NEW and UPDATE, use ordinary file tools to edit the authoritative live PLAN.md and implementation brief files. Never use file tools to alter immutable legacy snapshots, revisions, reviews, or logs; remaining references to those managed artifacts are transitional guidance pending phase 4.

Identify the first explicit verb (`init`, `new`, `update`, `annotate`, `finalize`, `go`, `help`) or infer one from the user's request. For NEW and UPDATE, select one unique repository-root plan by path and its plan files, and read it before acting; ask only for a material decision if the plan remains ambiguous. Read exactly the corresponding [workflow reference](references/workflows/) before acting. Preserve the user's request and intent, including visible completed task information; this is authoring input, not a managed revision transaction.

`new` creates a complete plan without launching an editor; `init` creates a phase-less draft and opens it. For NEW and UPDATE content changes, write the authoritative live PLAN.md and numbered briefs directly through successive normal read/write/edit calls, then read back each file. Invoke exactly one independently verified frontier/high-thinking `diffpi-plan-reviewer` per iteration; repair actionable findings and rerun it within bounded attempts. If effective model/thinking selection cannot be verified, fail preflight with the exact observed selection and required correction; do not silently promise runtime verification. Phase/task status and execution gates remain managed-tool concerns. The remaining init/annotate/finalize/go references retain old managed-tool calls only as transitional guidance until phase 4 replaces them; they must not be presented as Planner capabilities. `go` calls `plan_start_execution` before any code change; if the plan is draft or on the wrong branch, stop.

`--bg` requests one named background agent through `Agent` (Planner for authoring, Orchestrator for execution); pass the verb, exact arguments, cwd, and a `background: true` instruction. Remove `--bg` from the child's request and explicitly forbid redispatch. Return after launching it. A background child must not ask user questions. If `Agent` is unavailable, stop and report that background execution cannot be started; never silently execute inline. Without `--bg`, execute in the current turn: author as Planner, coordinate go as Orchestrator and delegate bounded Worker tasks; do not assume an inline mode switch occurred. Do not launch a multi-agent workflow unless the user explicitly opts into one.
