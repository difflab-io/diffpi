# Named plan evals

`mise run eval list` shows case names. `mise run eval show plan-tic-tac-toe` prints the exact prompts and Promptfoo config with its inline judge rubrics without calling a model. `mise run eval plan-tic-tac-toe --dry-run` checks fixture and extension availability. `mise run eval plan-tic-tac-toe` runs the live eval.

Each case has a JSON scenario and a readable Promptfoo YAML file with the same name in `evals/cases/`; judge rubrics live inline in that YAML. The runner uses Pi's SDK with Sol/high to run `/skill:plan new` then `/skill:plan update` in one isolated TypeScript fixture. It saves both full file snapshots, changed paths, ordered tool events, and observed Plan Reviewer tool results under `.tmp/evals/<name>-*/`. The initial request plans tic-tac-toe; the update requires Commander for the CLI command/options, the package dependency, and parsing tests.

Promptfoo's [Echo provider](https://www.promptfoo.dev/docs/providers/echo/) passes each **already generated** snapshot through unchanged. Its [llm-rubric assertion](https://www.promptfoo.dev/docs/guides/llm-as-a-judge/) compares the candidate with the actual plan skill, workflow, reviewer profile, and the user request. A small `evals/providers/pi-judge.ts` transport adapter sends Promptfoo's grading prompt to a separate read-only Pi Sol/high model session using your existing Pi auth; it does **not** inspect files or decide pass/fail. Only Promptfoo's model-graded verdict and threshold decide whether generated structure, quality, and skill standards pass. It writes full grading results to `promptfoo.json`, and a short score-plus-judge-reason summary to `verdicts.json`; `promptfoo.log` holds CLI details. A generator/runtime error is reported separately from a negative judge verdict. No text checks or `plan_verify` results are used as the eval's scoring rule.

The runner clones only a small fixture, never edits the main checkout, and removes copied credentials on exit. Pi and the `@tintinweb/pi-subagents` extension must already be installed. The judge makes model calls with the existing `openai-codex` authentication; there is no separate API-key requirement. Runs can take several minutes and retain failed plan artifacts for inspection. `promptfoo` is pinned in the root dev dependencies and requires Node.js 22.22 or newer; install with `bun install` before using `mise run eval`.

To add a new case, add a fixture, an `evals/cases/<name>.json` with prompts, and a matching Promptfoo YAML with inline `llm-rubric` assertions. The current runner's named cases use `new` and `update` stages.
